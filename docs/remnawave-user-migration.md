# Миграция пользователей Remnawave

Раздел доступен через:

```bash
sudo ./manage.sh
```

Выберите **«Перенос пользователей Remnawave»**.

## Назначение

Переносит учётные записи с локальной исходной панели `/opt/remnawave` на уже работающую целевую Remnawave Panel через HTTPS API. Конфигурация панелей, ноды и их сетевые настройки не переносятся.

## Требования

- Исходная панель в `/opt/remnawave` с `docker-compose.yml` и `.env`.
- Docker Compose, `jq`, `curl`.
- API token целевой панели.
- На целевой панели заранее созданы одноимённые Internal Squads.
- Для переноса пользователей scopes: `users:create`, `users:by-username`, `users:by-short-uuid`, `internal-squads:list`.
- Для read-only аудита связанных данных scopes: `users:by-username`, `nodes:list`.

## Перенос пользователей

Скрипт переносит username, статус, сроки действия, short UUID, VLESS/Trojan/Shadowsocks credentials, лимит и стратегию трафика, дату последнего сброса, описание, tag, email, Telegram ID, HWID device limit и членство в Internal Squads (сопоставление по имени).

Перед первой записью скрипт экспортирует и валидирует все записи, проверяет дубликаты идентификаторов и сверяет username/short UUID на целевой панели. При повторном запуске точные совпадения по username, short UUID и протокольным идентификаторам пропускаются; несовпадения блокируют перенос.

**Dry-run** выполняет проверки без POST-запросов. **Apply** требует отдельного подтверждения `yes`. Результаты записываются в JSONL-журнал с правами каталога `700` и файла `600` в `/var/lib/server-deployment/migrations/`. Журнал не содержит API token и протокольные credentials.

## Связанные данные

Отдельный read-only аудит проверяет таблицы:

- `user_traffic`
- `hwid_user_devices`
- `nodes_user_usage_history`
- `user_subscription_request_history`

Аудит считает агрегаты, сверяет пользователей и используемые ноды, проверяет осиротевшие ссылки. Значения IP и HWID не выводятся. Он не изменяет ни одну БД.

**Сами связанные данные пока не переносятся.** Не копируйте таблицы напрямую: необходимо remap-ить ID пользователей и нод и отдельно проверить конфликты на целевой стороне. Успешный аудит не является разрешением на запись.

## Ограничения и безопасность

- Используется только HTTPS; token вводится скрыто и передаётся curl через временный конфиг с правами `600`.
- Временные файлы создаются в каталоге с правами `700` и удаляются при завершении.
- Целевые пользователи не перезаписываются и не удаляются.
- Частичный Apply не откатывает уже созданные API-записи; сверяйте журнал и целевую панель перед повторным запуском.
- Перенос накопленных счётчиков трафика, HWID fingerprints, node usage history, subscription request history, внешних squad и node IDs пока не реализован.
